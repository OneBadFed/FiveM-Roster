# Public roster publishing audit

Reviewed linking and spreadsheet caching, private-tab blocking, sensitive-column masking, header detection, formula/value transfer, merges and preserved ranges, framed tables, Welcome snapshots, grid growth/trimming, dimensions, self-computing tabs, per-tab writer locks, pass leases, dirty flags, burst/catch-up triggers, sweep retries, and manual publication.

## October 7: special-cell publishing failures

Welcome, LOA Tracker and Patrol Log publication reported failed anchor writes without identifying the underlying Sheets error. The snapshot path now uses native `PASTE_VALUES` internally to freeze computed results, followed by native sheet/range copies to publish merged banners and in-cell images without serializing their objects through `setValue`. Rich text is restored explicitly. The Welcome public F6:W7 exception and its swap rollback remain in place.

Framed snapshots clear sensitive data columns and hidden left-border keys, remove notes/developer metadata, and trim unused rows/columns **before** copying across workbooks. Their public carrier now contains sanitized public content rather than an empty style carrier. Native failures propagate their original error instead of a generic cell count. Local regressions exercise native image/literal preservation, formula freezing, pre-transfer privacy, unused private rows, preparation failures, dimensions and cleanup. An additional shared Sheets-platform QA case tests native pasting over a merged banner with a formula, literal text and a long identifier; live execution remains outstanding.

## Fixes

- Welcome application status in **AA5:AA6** is outside the public-owned F6:W7 title exception and is mirrored. A startup/link sequence bug could leave departments without public edit/change/sweep triggers: startup deliberately skipped them while unlinked, but later linking did not install them. Link setup now installs them, and menu/control-panel force-publish verifies and repairs a missing or wrong-source set. Valid sets remain untouched. The shared installer retains staged-creation rollback and unrelated triggers. For an existing department, after deploying this fix, run **Roster → Install Triggers** once or force-publish once to repair its current trigger set. Direct edit failures/backoff/busy publishers also schedule the remaining work for catch-up. Local regressions cover AA5:AA6 routing, repeated open/closed values, the title exception, delayed edits, startup-before-link, idempotent installation, source/event checks, quota failure rollback and actual menu/link callers. Live trigger installation and dropdown edits have not been performed by the agent.
- Pass claims now use a short document lock, an owner-tagged lease and ownership-checked release. Concurrent publishers cannot both claim an idle property; an old owner cannot release a newer pass. Unreadable state fails closed. The ten-minute lease outlasts ordinary six-minute Apps Script execution limits.
- Partial cell-write errors propagate to the existing retry queue instead of merely logging success. Empty internal sheets clear stale public content while respecting preserved areas.
- Known header labels outweigh dense member data when detecting headers. Renamed private/system/form-response tabs are blocked using loaded configuration even when a secondary configuration read fails.
- Literal text beginning with `=` remains text during publication; actual formulas retain the existing transfer rules.
- Linking the internal workbook as its own public target is refused before changing the link. Link changes refresh the per-execution spreadsheet cache, and setup uses the serialized public publishing wrapper.
- Targeted Welcome publication resolves leading emoji differences. F6:W7 remains the sole Welcome exception; its public content and cell formatting are preserved while dimensions come from the internal sheet.
- Self-computing tabs no longer invoke broad automatic spill clearing. The former cleanup could remove unrelated neighboring content; blocked spill areas require deliberate repair in the public template.

## Efficiency

The update pipeline now has a scoped, document-locked work queue in `RosterPublishFast.gs`. Known ordinary-tab edits enqueue that tab; core roster/table edits and unscoped structural/format events retain a full pass to cover dependent views. Settled tables publish together in one pass. Subsequent catch-ups exclude those completed tables, and failures requeue unfinished tabs while retaining changes that arrived during the pass. Missing, invalid or oversized queue metadata falls back to a full pass. Paired installable `onChange` EDIT notifications no longer enqueue duplicate full updates after `onEdit`. Unknown script-write callers still safely mark all tabs dirty.

Welcome/framed rich text restores use adjacent rectangles instead of individual cell writes. The regression with a 100 × 40 static-text block takes **1 rich-text write instead of 4,000**. Mixed numbers/images remain native values, and merged anchors are written separately. Native snapshot copies still preserve formatting, images and the public Welcome F6:W7 exception.

An optional Sheets REST path reads complete dimension metadata in one request and applies contiguous dimension runs in batched requests. A 1,000-row/40-column fixture with two row-height bands uses **2 HTTP requests, zero individual source-dimension reads, and 3 dimension update requests in the batch**. Deep height synchronization of header-matched roster tabs also supports this path, including different source/destination row offsets. Only dimension metadata is requested; no cell data or private content is retrieved or transmitted by this path. Pending Sheets writes are flushed first. Sparse/invalid metadata, missing authorization, API restrictions or failed batch updates trigger the complete Apps Script fallback; no sizes are guessed and API failures are retried at most once per execution. The Sheets API must be available to the script's associated Cloud project for this optimization; no new Advanced Service dependency or credentials are required. These are local call-count measurements, not live timing claims.

The Apps Script dimension fallback still reads each source dimension and groups writes. Its 1,000-row/40-column fixture takes **3 grouped writes instead of 1,040 individual writes**. This preserves all dimensions when the optional API is unavailable.

Catch-up scheduling now uses a short atomic claim and a two-minute pending lease, while retaining the requested three-second minimum delay. The old three-second marker could expire before Google delivered the trigger, causing ongoing edits to repeatedly delete and replace it. Cleanup checks trigger ownership so an old event cannot delete a newer trigger. Actual delivery remains controlled by Google; the minute sweep remains the backstop. [Google's timing documentation](https://developers.google.com/apps-script/reference/script/clock-trigger-builder#afterdurationmilliseconds) describes `after` as a minimum delay.

Source/public sheet inventories are read once per pass. Under each tab's writer lock, recovery checks now use one fresh property snapshot instead of four service reads; this check is repeated for each tab so a new recovery record cannot be missed. An interrupted writer stops the remaining pass rather than logging the same error for every tab. Full and slow background publishes log total duration and per-tab duration to SYS Log, exposing remaining live bottlenecks without an extra telemetry system.

A durable, owner-tagged work checkpoint is stored before taking queued work. If Google terminates execution before retry/cleanup runs, a subsequent publisher recovers it after the ten-minute pass lease expires, merging it with later edits. Normal completion clears only its own checkpoint. Passes yield between tabs after 4.5 minutes so unfinished work can be queued before the normal Apps Script execution limit; a single slow Google service call cannot be interrupted and is covered by the durable checkpoint. Recovery cannot make partially written Google sheets transactional, but it prevents a stopped execution from silently discarding updates.

The existing spreadsheet memo, burst guard, deferred rebuilds, interactive backoff, serialized pass leases and idle sweep remain. Whole-sheet fingerprints were deliberately not introduced: incomplete fingerprints could miss borders, images, merges, conditional rules, rich text or public drift and incorrectly skip updates.

Full Welcome copying and scanning dependent public formulas remain significant costs. Native Welcome snapshots preserve sheet objects but replace the public tab ID. Refer to WELCOME_AUDIT.md for direct-link limitations, formula-result snapshot behavior and the live template checks still needed. Unknown structural changes may still require a full workbook pass.

## Verification

Expanded `tools/publishcheck.js` covers failure retries, clean passes, settled-table updates, lease contention and ownership, literal/formula behavior, dense-data header detection, dimension write counts, and empty-source cleanup/failure. `tools/welcomecheck.js` covers the F6:W7 exception, snapshot dimensions/style metadata, public formula references and swap rollback. Table and other repository regression checks also pass locally.

`tools/publishfastcheck.js` exercises the actual queue wrappers and publish orchestration: concurrent changes, partial/full retries, malformed/oversized scopes, legacy dirty flags, emoji Welcome aliases, private-tab blocking, cached inventories, late recovery checkpoints, hard-stop recovery, execution budget yielding, dimension API batching/chunking/fallback, rich-text rectangles/merges and delayed catch-up ownership. `node tools/qa.js` runs **21 suites/checks** including the new regressions and Apps Script/HTML syntax checks.

No live spreadsheet was modified or benchmarked for this audit. Before production deployment, use a test internal/public pair to check permissions, renamed/added columns, sensitive columns, formulas/spills, in-cell images/smart chips, charts/drawings, title preservation, structural and formatting-only edits, simultaneous submissions and publication, retry recovery, direct links and Apps Script quotas/timeouts. Google service failures and external user edits make publication nontransactional.

Deployment uses the repository's Sync Apps Script workflow on pushes to `main`. Confirm that workflow succeeds before checking live performance; local regressions do not establish deployment or live timing.

## Trigger installation contention

The reported `Install Triggers` failure at `replaceManagedTriggers_` was an eight-second timeout on the script lock. That lock is also held by public-sheet copying, roster changes and background rebuilds, so the message did not establish that another installer was running. Core/extras replacement, public-trigger verification and audit-trigger setup now use the user lock: `ScriptApp.getProjectTriggers()` returns the current user's inventory. Trigger setup remains serialized for that inventory while ordinary writer work retains the script lock. Nested verification does not release its caller's lock; creation failures still roll back staged replacements. A genuinely competing setup still fails before altering triggers. [Google's lock scopes](https://developers.google.com/apps-script/reference/lock/lock-service) and [trigger inventory scope](https://developers.google.com/apps-script/reference/script/script-app#getProjectTriggers()) describe this distinction.

`tools/startupcheck.js` now runs the complete installer with the writer lock unavailable, exercises competing user-lock ownership and invokes the real audit installer for duplicate cleanup, cached opens, nested ownership and failed creation. After uploading this fix, run **Roster → Install Triggers** again; this upload does not itself create the live triggers. The original timeout occurred before the core replacement began, so that failed attempt did not install the publishing triggers.
